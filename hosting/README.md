# Перенос «Зарубы» на обычный хостинг

Эта версия использует прежний интерфейс React и лёгкий сервер PHP. Все оплаты и фотографии хранятся на выбранном хостинге и видны всем посетителям. Внешняя база данных и постоянно запущенный Node.js не нужны. Вход администратора, повторные оплаты одного менеджера, рейтинг и обновление каждые 10 секунд сохранены.

## Требования

- Linux, PHP 8.1+ (предпочтительно актуальная поддерживаемая версия), расширения `mbstring`, `intl`.
- Apache с `mod_rewrite`, разрешёнными `.htaccess` и директивами `Options`/`Require`, либо эквивалентные правила Nginx.
- HTTPS и место для файлов. Рекомендуемый диск от 1 ГБ.
- PHP должен иметь доступ на чтение и запись к папке данных. `upload_max_filesize` от 5M, `post_max_size` от 6M.

Для Nginx маршрут `/api/` передаётся в `api.php` через FastCGI с исходным `REQUEST_URI`. Фотографии не должны перехватываться правилом отдачи статических JPG/PNG: они находятся за пределами корня сайта.

## Сборка и экспорт

1. `node node_modules/vite/bin/vite.js build --config hosting/vite.config.ts`
2. `node --use-env-proxy scripts/export-shared-host.mjs https://адрес-старого-сайта work/новая-резервная-копия`
3. Передать пароль администратора через переменную окружения `MIGRATION_ADMIN_PASSWORD`.
4. `node scripts/package-shared-host.mjs --backup work/новая-резервная-копия --out outputs/новый-перенос --origin https://новый-домен --php путь-к-php`

Пакет проверяет контрольные суммы всех фотографий и JSON, число записей и общую сумму. Пароль преобразуется в хеш, ключ сессии генерируется заново. Папка назначения должна быть новой: скрипт отказывается перезаписывать существующие данные. Если адрес пока неизвестен, `--origin` можно пропустить: чтение работает, вход и изменения закрыты до настройки адреса.

## Установка

1. В панели хостинга создать сайт, включить HTTPS и PHP с нужными расширениями.
2. Загрузить содержимое `public_html` в корневую папку сайта, включая скрытые `.htaccess` и `.user.ini`.
3. Загрузить `zaruba-data` на один уровень выше корневой папки сайта. Например, для `/domains/example.ru/public_html` путь данных должен быть `/domains/example.ru/zaruba-data`. Папка данных содержит секреты и должна оставаться ВНЕ каталога, доступного через интернет.
4. В `zaruba-data/config.php` должна возвращаться конфигурация с `origin`, равным точному HTTPS-адресу сайта без завершающего слеша, `passwordHash` и `sessionSecret`. Если пакет собран без адреса, пересобрать в новую папку с `--origin` до загрузки.
5. Проверить главную страницу, семь/актуальное число оплат, суммы, все фотографии и вход ADMIN. Сравнить `/api/payments` с экспортом. Проверить, что из интернета недоступны `zaruba-data`, конфигурация, JSON и резервные копии.

## Переключение без потери оплат

Во время первого теста старый сайт продолжает работать. Перед окончательным переходом договориться о короткой паузе в редактировании, повторить экспорт и установить свежую копию данных на новый сайт. Сверить записи и фотографии, затем использовать новый адрес. Старый и новый сайты после переноса являются независимыми: новые оплаты нужно добавлять только на новом адресе.

При обновлении кода загружать только `public_html`. **Никогда не заменять рабочую `zaruba-data` старой копией.** Исходные заполненные данные, архив установки и секреты нельзя публиковать в GitHub.

## Надёжность

Изменения сериализованы файловой блокировкой и проверяют версию записи. Сохранение выполняется через временный файл и атомарное переименование. Перед изменением создаётся копия; хранятся 50 последних копий. Фотографии остаются для повторных оплат и восстановления. Номера версий не сбрасываются при освобождении и повторном заполнении монетки.

Сессия администратора — подписанная HttpOnly/SameSite cookie на 12 часов. Изменения принимаются только с настроенного адреса сайта. Ограничены попытки входа и размер фотографий; содержимое изображения проверяется сервером. Дополнительно рекомендуется включить резервное копирование всего аккаунта в панели хостинга.

## Проверка без изменения опубликованных данных

Изолированный PHP-сервер запускается с отдельной тестовой папкой и `hosting/router.php`. `tests/api-smoke.mjs` разрешает только localhost и требует пустую тестовую базу. Заполненный пакет проверяется только чтением. Все проверки на реальном хостинге выполняются до переключения пользователей.
